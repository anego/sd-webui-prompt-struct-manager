# ログ出力に関する厳格なルール (Logging Strict Rules)

TypeScriptなどJavascript系のコードを書く場合、以下のログ出力ルールを厳守すること。

## 1. 禁止事項
* **`console.log` の使用禁止:** デバッグ目的であっても、原則として `console.log` の使用を禁ずる。必ず目的に応じた適切なログレベルや出力メソッド（後述）を選択すること。
* **`any` 型の排除:** ログ出力に渡すオブジェクトやペイロードの型定義に `any` を使用しないこと。
* **無意味な値のダンプ禁止:** 変数の中身だけを無言で出力しないこと。
* **グループの閉じ忘れ禁止:** `console.group` または `console.groupCollapsed` を呼び出した際は、必ずスコープの最後（または `finally` ブロック）で `console.groupEnd` を呼び出すこと。

## 2. ログメソッドの使い分け
状態の重要度やデータ構造に応じて、以下のメソッドを正確に使い分けること。

### データの構造化・可視化
* **`console.table()`**
  * **用途:** オブジェクトの配列や、同種のプロパティを持つデータのリストを二次元表形式で出力する。
  * **出力例:** APIからフェッチしたユーザー一覧、マスタデータのリストなど。
* **`console.dir()`**
  * **用途:** 複雑な階層を持つオブジェクトや、DOM要素、Vueのリアクティブオブジェクト（Proxy）の内部構造を、展開可能なツリー形式で出力する。
  * **出力例:** 巨大なJSONペイロードの構造確認、引数として渡された複雑な設定オブジェクトの詳細確認など。

### 処理のグループ化
* **`console.group()` / `console.groupCollapsed()`**
  * **用途:** 一連の関連する処理（トランザクション、APIリクエストのフロー、複雑な状態更新など）を視覚的にまとめる。
  * **使い分け:**
    * `group()`: エラー調査時などに必ず目視したい重要な処理のまとまりに使用する。
    * `groupCollapsed()`: デフォルトでは折りたたんでおき、必要な時だけ展開して詳細を確認したい場合（コンポーネントのライフサイクルや定期実行処理など）に積極的に使用する。

### ログレベル（状態の通知）
* **`console.debug()`**
  * **用途:** 開発環境でのみ必要な詳細なトレース情報。（通常は `groupCollapsed` の中で使用される）
  * **出力例:** 関数の入出力パラメータ、ループ内の細かい処理状況、早期リターン時の条件判定の結果など。
* **`console.info()`**
  * **用途:** アプリケーションの正常な状態遷移、ユーザー操作の完了、重要なマイルストーン。
  * **条件:** システムが意図通りに動いていることを証明するための「意味のある情報」のみを出力する。
* **`console.warn()`**
  * **用途:** エラーではないが、注意が必要な予期せぬ状態。
  * **出力例:** 非推奨関数の呼び出し、APIレスポンスの欠損（デフォルト値でフォールバックして処理を継続した場合）など。
* **`console.error()`**
  * **用途:** 致命的なエラー、処理の継続が不可能な状態。
  * **出力例:** API通信の失敗（HTTP 4xx, 5xx）、予期せぬ例外（`catch` ブロック内）、データ不整合による画面描画のパニックなど。

## 3. メッセージの記述方針 (Why over What)
コメントの記述方針と同様に、ログメッセージも「何を出力しているか（What）」ではなく、**「なぜそのログが出力されたのか（Why）」** というコンテキストを必ず含めること。

* ❌ 悪い例: `console.info(userData);` または `console.table(users);`
* ⭕ 良い例: `console.info('[PSM][Auth] ユーザー認証が完了し、セッション情報を初期化しました。', { userId: userData.id });`
* ⭕ 良い例: `console.table('[PSM][UserList] 画面描画用にフィルタリングされた有効なユーザー一覧', activeUsers);`

## 4. フォーマット
ログを視覚的に追いやすくするため、可能な限りプレフィックス（モジュール名やコンポーネント名）を付けること。
例: `[UserStore]`, `[HeaderComponent]`, `[API/Fetch]`
