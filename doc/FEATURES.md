# Prompt Struct Manager - 機能仕様書

## 1. プロンプト管理機能

### 1.1 階層構造 (Tree Structure)
- **Positive / Negative:** 2つの独立したツリーでプロンプトを管理。
- **グループ化:** フォルダを作成し、プロンプトをカテゴライズ可能。
- **無限ネスト:** グループの中にさらにグループを作成可能（深さ制限なし）。
- **並べ替え:** ドラッグ用ハンドルアイコン（縦二列の点）がグループおよびプロンプトの左側に追加され、ドラッグ＆ドロップによる直感的な並べ替えが正確に行えます。
- **長文表示保護 (編集アイコン消失防止):** プロンプトの名前や内容が極端に長い場合、チップテキストの最大幅が自動で縮小（110px）され、かつ flex-shrink 属性が最適化されるため、右端の編集（鉛筆）アイコンが画面外に押し出されることなく常時表示・クリック可能です。

### 1.2 プロンプト編集・調整
- **有効/無効切り替え:** チェックボックスにより、プロンプトを削除せずに一時的に無効化可能。親グループを無効化すると子要素もすべて出力から除外される。
- **重み付け (Weight):** 各プロンプトチップの右横にコンパクトなスライダーUI（`0.1`〜`2.0`）を搭載。ドラッグして直感的に重みを調整可能。スライダー右端のリセットボタン「↺」で即座に `1.0` に戻せます。
- **スライダー表示切り替え:** 設定画面（歯車アイコン）の「重みスライダーを表示」設定から、スライダーの表示/非表示を切り替え可能。設定値はブラウザをリロードしてもLocalStorageに記憶・維持されます。
- **アンダーバーの自動スペース置換:** プロンプト内容にアンダーバー（例: `sway_back`）が含まれている場合、コンパイルしてWebUIに反映される際に自動的に半角スペース（`sway back`）へ置換されます。ただし以下のトークンは構造がそのまま維持（保護）されます。カンマ区切りで複数タグを含むアイテムでも、トークン単位で判定されます。
  - Dynamic Promptsのワイルドカード記述（例: `__character__`）
  - スコアタグ（`score_7`, `score_8_up` など。Anima / Pony系で使用）
  - 3文字の顔文字タグ（`^_^`, `>_<`, `@_@`, `0_0` など）
  - 拡張ネットワーク構文（`<lora:name_v2:0.8>`, `<hypernet:...>` など）
- **BREAK区切りの強調表示:** 内容が `BREAK` のみのアイテムは、通常のチップではなく `<hr>` のように**横幅いっぱいの区切り線**（オレンジの破線＋中央ラベル）として表示され、プロンプトの区切り位置が一目で分かります。ドラッグでの移動、ダブルクリック編集、有効/無効の切り替えは通常のアイテムと同様に行えます（無効時はグレーの破線＋取り消し線）。
- **入力補完連携 (Tag Autocomplete):** 拡張機能 `a1111-sd-webui-tagcomplete` が有効な場合、プロンプト入力時にタグ候補の自動補完が利用可能。
- **メモ機能:** 各プロンプトに対して、ツールチップ等で確認可能なメモを付与可能。

### 1.3 カテゴリ内排他選択（択一モード）
- **動作仕様:** グループ（カテゴリ）ヘッダーの右端に択一トグルボタン（ティールブルー色）を配置。
- **排他制御:** 択一モードが有効なグループ内において、あるプロンプトを有効化（チェック）すると、そのグループ内の他のすべての兄弟プロンプトが自動的に無効化（チェック解除）されます。
- **複数有効時のON化:** 既に複数のプロンプトが有効になっている状態で択一モードを有効にした場合、最初の有効プロンプト1つだけを残して他のプロンプトは自動的に無効化されます。
- **Dynamic Prompts連携:** グループ内のプロンプトからランダムに1つを選択して生成する `{A|B|C}` 構文に対応。
- **専用スイッチ:** グループ名の横にある "Randomize Group" スイッチで簡単にON/OFF可能。
- **視認性:** ランダムモード時はグループ全体が紫色の点線枠で強調表示される。

### 1.4 一括操作 (Bulk Toggle)
- **Hover Actions:** グループヘッダーにマウスをホバーすると、一括操作用のアイコンが出現。
- **Enable All:** `[☑☑]` アイコンでグループ内の全アイテムを有効化。
- **Disable All:** `[☒]` アイコンでグループ内の全アイテムを無効化。

### 1.5 反映前プレビュー (Apply Preview)
- **プレビューボタン:** ツールバーの「反映＆閉じる」の左にある「プレビュー」ボタンから、WebUIへ反映する前に出力内容を確認できます。
- **コンパイル結果の全文表示:** Positive / Negative それぞれの最終的な出力文字列を表示します。Animaモードではカテゴリ整列を適用した実際の順序で確認できます。
- **タグ単位の差分:** 現在のWebUIテキストエリアの内容と比較し、追加タグを緑・削除タグを赤（取り消し線）・共通タグを枠線チップで表示します。同一タグの重複は出現回数で比較されます。
- **統計表示:** タグ数・文字数と、追加/削除数（`+3 / -1`）を表示します。差分がない場合は「変更なし」と表示されます。
- **トークン数の概算:** `≈30 トークン (1×75)` の形式で表示します。ペインヘッダー（Positive / Negative）にもライブ更新される概算値が表示され、SD系モードでは75トークンのチャンク境界を超えると警告色になります。
  - 拡張ネットワーク構文（`<lora:...>`）や強調構文の括弧・重み指定はエンコード対象外のためカウントされません。`BREAK` はチャンク境界を強制するものとして扱われます。
  - あくまで概算です（正確な数はモデルのトークナイザに依存します）。Animaは別トークナイザ（Qwen3系）でチャンク概念がないため、チャンク表示は行われません。
- **そのまま反映:** モーダル内の「このまま反映」ボタンから、通常の反映処理（重複チェックを含む）を実行できます。

### 1.6 サブ分類による自動グループ化 (任意のタイミングで実行)
- **実行方法:** グループを右クリック →「サブ分類でグループ化」。そのグループ**直下**のタグアイテムを、髪・服装・ポーズなどのサブグループへ再編成します（取込時と同じ13分類＋その他。詳細は§3.2）。
- **既存構造の保持:** 直下にある既存のサブグループは元の位置のまま残り、葉アイテムのみがグループ化されます。自然言語アイテム・`<lora:...>`・ワイルドカード・`BREAK` は対象外で位置も維持されます。
- **実行条件:** 直下の対象タグが8件以上あり、サブ分類が2種類以上検出された場合のみ再編成します（条件を満たさない場合はメッセージを表示して何も変更しません）。
- **AI補完:** 翻訳設定にOpenAI互換バックエンド（LM Studio / Ollama 等）が設定されている場合、メニューに「サブ分類でグループ化 (AI補完)」が追加されます。
  - **ハイブリッド方式:** まずルールベースで判定し、**判定できなかったタグのみ**をローカルLLMへ問い合わせます（20件ずつ）。リクエスト数と待ち時間を抑えつつ、ルールでは拾えないタグを補えます。
  - AIの応答は許可された分類キーのみ受け付け、不正な応答や失敗時はルールベースの結果のみを使用します（処理は中断されません）。
  - 実行中は操作不可のローディングオーバーレイと進捗が表示されます。
- PNG Info取込ダイアログにも同じAI補完オプション（「未分類タグをAIで補完する」）があります。

### 1.7 重複チェック (Duplicate Detection)
- **自動検出:** ツリー内で同じテキストを持つプロンプトが複数存在する場合、自動的に検出しハイライト表示します。
- **検証モードの切り替え:** 設定画面から、重複検出時の動作を `None` (無効), `Warn` (警告表示のみ), `Error` (重複時は出力や生成をブロック) の3段階から選択可能です。
- **特殊プロンプトの除外:** `BREAK` や一部の制御トークンなど、構造上複数回使用される意図がある単語は重複判定から除外されます。

### 1.8 プロンプト大辞典との双方向連携
- **ポータル移動:** プロンプト編集モーダルを開いた瞬間、別拡張機能である「プロンプト大辞典 on SDwebUI」のDOM要素を事前検知し、モーダル内のポータルプレースホルダーへラグなしで即座にテレポート（移動マウント）させます。
- **クリックインターセプト & タグ挿入:** モーダル展開中、大辞典の「挿入」ボタンをクリックすると、WebUI本体への入力ではなく、PSM編集モーダルのプロンプト本文エリアへカンマ区切りで自動的にタグを追記します。
- **左右分割（2カラム）スクロールレイアウト:** 大辞典連携時はモーダル幅が自動的に `1100px` の2カラム表示（左側：PSM編集フォーム、右側：大辞典検索画面）に拡張され、右側の大辞典エリアは独立して縦スクロールが可能です。これにより、モーダル下部の決定・キャンセル・削除ボタンが隠れることなく常時固定表示されます。
- **クリーンな復元:** 編集完了またはキャンセルでモーダルが閉じられた際、大辞典パネルを元の親要素（`txt2img_actions_column` など）へ自動的に復元マウントし、自動的に折りたたみ状態に戻します。
- **検索キーワード of 自動コピー:** タグを挿入する際、大辞典の検索入力欄（`input.pd-inline-query`）に入力されているテキストを、編集中のプロンプトの名前フィールドへ自動的にコピーします（名前フィールドが現在空欄である場合のみコピーし、既に名前が存在する場合は上書きしません）。
- **フォールバック設計:** 大辞典がインストールされていない（またはDOM要素が見つからない）環境では、モーダルは自動的にスリムな1カラム（幅 `600px`）で表示され、大辞典ポータル部分は非表示（`display: none`）にフォールバックされます。JSのエラー等も一切発生しません。

## 2. ユーザーインターフェース (UI/UX)

### 2.1 Group Map (グループマップ)
- 画面右側に常駐するナビゲーションバー。
- **機能:** 現在のツリー構造（グループのみ）を一覧表示。
- **クリックジャンプ:** 項目をクリックするだけで、該当するグループの位置まで自動スクロール。
- **視認性:** 深い階層構造に対応するため、インデントガイド（縦線）を表示して親子関係を可視化。
- **プロンプト数表示:** 各グループ名の横に、そのグループ内で有効なプロンプトの総数を表示。

### 2.2 ショートカットキー
- **Global Toggle:** 設定によりカスタマイズ可能（デフォルト: なし）。PSMパネルの表示/非表示を切り替え。
- **反映して閉じる:** `Ctrl + Shift + Enter` で現在のプロンプトをWebUIに反映し、パネルを閉じる。
- **キーボードナビゲーション:** 矢印キーでアイテム移動、F2で編集、Spaceで有効/無効切り替えが可能。

### 2.3 テーマとスタイル
- **Dark Mode:** WebUIのダークテーマに親和性の高いデザインを採用。
- **Vuetify 3:** マテリアルデザインベースのコンポーネントを使用。
- **Embedded Icons:** MDIアイコンフォントをインライン埋め込みし、描画崩れを防止。
- **Dynamic Prompts:** `__name__` 形式 of プロンプトを自動検出し、シアン色+イタリック+専用アイコンで強調表示。ボタン形状も丸みを帯びたデザインに変更され、一目で区別可能。

### 2.4 初期セットアップウィザード (Setup Wizard)
- 初回起動時（または設定ファイル未検出時）に、保存先ディレクトリの選択と初期ファイルの作成をガイドするウィザードを表示。
- 以前の設定（WebUI側の設定）が残っている場合は自動的にそのパスを提案し、スムーズな移行をサポート。

### 2.5 マウス操作
- **ダブルクリック編集:** グループまたはプロンプトアイテムをダブルクリックすることで、素早く編集モード（設定モーダル）を開くことが可能。
- **右クリックメニュー:** アイテム上で右クリックするとコンテキストメニューを表示し、詳細な操作（複製、削除、移動など）にアクセス可能。

### 2.6 検索フィルター機能 (Search Filter)
- **ペイン独立フィルター:** サイドバーにあった共通の検索フィルターを廃止し、Positive と Negative のペインヘッダー部にそれぞれ独立した検索フィルターを配置。
- **開閉連動による非表示化:** ペインが閉じられている状態（折りたたみ時）は、フィルター入力欄が自動的に非表示になります。
- **誤動作防止設計:** フィルター欄のクリックやキー入力によってペインが意図せず開閉（トグル）しないよう、イベントの伝播（バブリング）が防止されています。

## 3. ファイル・設定・プロファイル管理

### 3.1 YAML永続化
- プロンプトデータはYAML形式でローカルディレクトリに保存される。
- **複数ファイル管理:** 用途に応じて複数のYAMLファイルを作成し、プルダウンで切り替え可能。
- **ファイル操作:** 新規作成、複製、リネーム、削除が可能。

### 3.2 PNG Info (infotext) 取込
- **機能概要:** ツールバーの画像アイコン（🖼️）から、生成画像のパラメータ文字列（PNG Infoタブの内容）を貼り付けてプロンプトを構造化して取り込めます。
- **自動解析:** Positiveプロンプト、`Negative prompt:` 行、`Steps: 20, Sampler: ...` の生成設定行を自動的に判別します。複数行のプロンプトや、Negative・設定行が無いケースにも対応します。
- **構文の解析と復元:**
  - 強調構文 `(smile:1.2)` はウェイト値として取り込まれます。`((detailed))` `[dark]` のような括弧の重ねがけも `1.1^n` で概算されます。
  - エスケープされた括弧 `\(...\)` は通常の括弧に復元されます（出力時に再エスケープされるため、そのまま元の表記へ戻ります）。
  - `<lora:...>`・ワイルドカード `__name__`・`BREAK` は分解せず1アイテムとして保持されます。
  - 句点で終わる文や単語数の多い長文は、自動的に「自然言語アイテム」として取り込まれます。
- **カテゴリ別グループ化:** 「カテゴリ別にグループ化する」をONにすると、タグDB（tagcomplete）による判定結果をもとに品質・主体・キャラクター・作品・絵師・一般のグループへ自動振り分けします（Animaモードでは既定でON）。タグDBが利用できない場合はフラットな構成で取り込まれます。
- **「一般」グループの細分化:** Danbooruのタグ種別では大半が `general` に集まり一般グループが肥大化するため、「『一般』を髪・服装などに細分化する」（既定ON）でサブグループへ振り分けます。
  - サブ分類は「構図・視点／顔・表情／髪／体・体型／服装／装飾品・小物／ポーズ・動作／小物・シンボル／背景・場所／光・色／画風・画材／効果・演出／文字・注記」の13種類＋「その他」です。
  - タグ文字列のキーワードで判定します（単語境界を見るため `chair` が `hair` に誤一致しません。複数形 `earrings` も解決します）。`^_^` や `:d` のような顔文字タグは「顔・表情」に分類されます。
  - 一般タグが8件未満の場合、またはサブ分類が実質1種類しか付かない場合は細分化せずフラットなまま取り込みます。
  - 高頻度のDanbooru一般タグ1000件での実測分類率は約75%です（残りは人数タグなど上位カテゴリで扱われるものが大半）。
- **タグ名の日本語化:** 「タグ名を日本語訳して『名前』に入れる」をONにすると、翻訳機能（§4.3の設定を使用）で英語タグを日本語訳し、各アイテムの「名前（表示用）」に設定します。
  - 20件ずつ番号付きリストで一括翻訳するため、タグ数が多くてもリクエスト数を抑えられます。
  - 処理中はファイル読込時と同じ操作不可のローディングオーバーレイが表示され、翻訳の進捗（`12 / 45` とプログレスバー）を確認できます。
  - 翻訳方向は自動的に英語→日本語へ切り替わります（DeepL利用時は `target_lang=JA`、OpenAI互換利用時は専用のシステムプロンプト）。
  - 対象は名前が空のタグアイテムのみです。既に名前があるアイテム、自然言語アイテム、`<lora:...>`・ワイルドカード・`BREAK` はスキップされます。
  - 翻訳に失敗した場合や番号の対応が取れなかった項目は名前が空のまま取り込まれ、取込自体は中断されません。
- **取込先の選択:** 現在のファイルへ上書き、または新規ファイルとして保存を選べます。貼り付けた内容はダイアログ内でタグ数・生成パラメータのプレビューとして即時確認できます。

### 3.3 プロファイル（状態スナップショット）
- **機能概要:** 現在編集中のツリーの全プロンプトの有効/無効状態（`enabled`）および重み設定（`weight`）の組み合わせを「プロファイル」として名前を付けて保存できる機能。
- **一括適用・復元:** 保存されたプロファイルをツールバーのドロップダウンから選択するだけで、保存時の状態にツリー全体が一括して復元されます。
- **保存スキーマ:** 各YAMLファイル内の `profiles` 項目に配列形式で永続化保存されます。
- **削除機能:** 不要になったプロファイルはドロップダウンから個別に削除可能です。

### 3.4 グローバル設定
- **UIスケール:** Small / Medium / Large の3段階調整。
- **言語設定:** 日本語 / 英語 切替対応。
- **保存先 (Storage):** 「ショートカット・保存先」グループ内でYAMLファイルの保存先フォルダを変更可能。
- **ファイルリスト更新:** 更新ボタンにより、外部で変更されたファイル構成を再読み込み可能。
- **サイドバーのグループ化とスクロール:** 「ファイル操作」「モデルモード」以外の設定項目は「表示・チェック設定」「ショートカット・保存先」「翻訳設定」の折りたたみパネルに整理されています。項目がサイドバーの高さを超える場合は自動的に縦スクロールバーが表示されます。

### 3.5 非同期処理中のローディングインジケーター
- **多重度カウンタ制御:** ファイルの初期読み込み、ファイルリスト取得、ファイル操作（新規作成、複製、リネーム、削除）、PNG Info取込、タグ名の翻訳、カテゴリ一括判定の実行中に、画面全体をカバーする操作不可のローディングオーバーレイUI（`v-overlay`）を自動表示します。ネストした処理でも最初の処理内容のメッセージが維持されます。
- **件数付き進捗表示:** タグ名の一括翻訳のように件数が判明している処理では、スピナーの下に `12 / 45` の進捗とプログレスバーを併記します。
- **保存処理時のロック排除:** プロンプトの有効/無効化や重み調整時などの自動保存処理（`savePrompts`）時にはローディングスピナーを表示せず、ユーザーの連続的な操作をロックしない設計になっています。
- **操作インターロック:** ローディング表示中は画面内のすべてのボタンやツリー操作がブロックされるため、ユーザーによる二重クリックや他操作によるデータの破損・不整合を完全に防止します。
- **進行状況テキスト:** 中央にローディングスピナー（`v-progress-circular`）とともに、処理内容に応じた「読み込み中...」「保存中...」などの多言語解決された進捗メッセージが表示されます。

## 4. Animaモデル対応・翻訳機能

### 4.1 モデルモード (Model Mode)
- **ファイル単位の切替:** サイドバーの「モデルモード」トグルで `SD系` / `Anima` を切り替え。設定はYAMLファイルのルート（`model_mode`）に保存され、ファイルごとに独立します。
- **後方互換:** `model_mode` 未定義の既存YAMLは自動的に `SD系` として扱われます。

### 4.2 自然言語アイテム (Natural Language Item)
- **用途:** Anima等の自然言語プロンプト対応モデル向けに、長文をそのまま出力するアイテムタイプ。
- **動作:** 編集モーダルの「自然言語モード」スイッチをONにすると、アンダーバー置換・括弧エスケープ・末尾カンマ除去をすべてスキップし、原文のまま出力します（重み `(text:w)` は適用可能）。

### 4.3 プロンプト翻訳 (日本語 → 英語)
- **翻訳ボタン:** 自然言語アイテムの編集時に「原文」欄と「英訳 →」ボタンが表示され、日本語原文をローカルLLM/クラウドAPIで英訳して内容欄へ反映します。原文は `sourceText` として保持され、出力には含まれません。
- **2プロファイル切替:** サイドバー「翻訳設定」で `ローカル` / `クラウド` の2プロファイルを常時保持し、トグルで切替（再入力不要）。
- **対応バックエンド:** OpenAI互換API（Ollama / LM Studio / llama.cpp server / OpenAI / OpenRouter 等）および DeepL API。プリセット選択でエンドポイント等を自動入力。
- **設定の保存先:** APIキーを含む翻訳設定はブラウザの `localStorage`（`psm_translate_settings`）にのみ保存され、サーバー側には保存されません。クラウド利用時は外部送信の注意書きが表示されます。
- **接続テスト:** 設定パネルの「接続テスト」ボタンで固定短文の試訳を実行し、結果またはエラー詳細（モデル未検出等のサーバーメッセージ含む）をインライン表示します。

### 4.4 カテゴリ整列 (Anima推奨タグ順序)
- **カテゴリ属性:** グループに `品質/メタ/年代/安全` `主体` `キャラクター` `作品` `絵師` `一般` のカテゴリを設定可能（グループ編集モーダル）。
- **カテゴリバッジ:** 設定したカテゴリはグループヘッダのグループ名右横に色分けバッジで表示されます（`一般` と未設定は非表示）。
- **カテゴリ自動判定:** `a1111-sd-webui-tagcomplete` のタグデータベース（`tags/danbooru.csv`）を参照し、グループ配下のタグから多数決でカテゴリを判定します。
  - グループ編集モーダルの「カテゴリ自動判定」ボタン: 判定結果をカテゴリ欄に反映し、内訳（例: 「12件中: キャラ8 / 一般3 / 不明1」）を表示します。完了ボタンを押すまで保存されません。
  - サイドバーの「カテゴリ一括判定」ボタン（Animaモード時のみ表示）: カテゴリ**未設定**のルートグループのみを判定して適用します。設定済みグループは変更されません。
  - Danbooruのタグ種別（general / artist / copyright / character / meta）をPSMカテゴリへ対応付け、`1girl` `solo` などの人数・主体タグは `主体` に振り分けます。エイリアス（`longhair` → `long_hair` 等）からも判定可能です。
  - tagcompleteが未導入の場合はエラーメッセージで案内されます（機能自体は任意）。
- **ヘッダ背景色:** グループ編集モーダルでヘッダの背景色を設定可能。ダークテーマに馴染むプリセット8色に加え、カラーピッカーによるカスタム色の指定、「色なし」でのクリアに対応。設定はYAMLの `headerColor` に保存されます。
- **出力時整列:** Animaモード時のみ、WebUIへの反映時にルート直下をカテゴリ優先度で安定ソートして出力します。ツリー表示・保存順は変更されず、同一カテゴリ内の相対順序も維持されます。
- **後方互換:** カテゴリ未設定は `一般` 扱いのため、既存YAMLの出力順は変わりません。SD系モードでは整列は行われません。

### 4.5 Animaテンプレート
- **新規作成オプション:** 新規ファイルダイアログの「Animaテンプレートで作成」スイッチをONにすると、カテゴリ設定済みのグループ雛形（品質・年代・主体・キャラクター・作品・絵師・一般）、Anima公式推奨の品質タグ・ネガティブタグ、およびAnimaモードで初期化されます。

## 5. 開発者機能 (Dev Mode)
- **Debug Log:** `src/log.ts` により、開発モード時のみ詳細なデバッグ情報をコンソールに出力。
- **Import:** 開発者モード時のみ、外部からのインポート機能（実験的機能）がUIに表示される。
